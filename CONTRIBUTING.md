# Cómo trabajamos en training-web

## Ramas
Nombramos las ramas con `tipo/descripcion-corta`, en minúscula y con guiones.
Ejemplo: `docs/readme`, `feat/login`.

## Commits
Usamos `tipo: qué hiciste`, en minúscula y en presente.
Tipos: feat, fix, docs, chore.
Ejemplo: `docs: agrega el readme de la empresa`.

## Revisión de Pull Requests
Cada integrante revisa los Pull Requests del otro.
Antes de aprobar miramos que los archivos sean los correctos, que no haya errores de escritura y que el commit siga la convención.

## Cuándo se aprueba un Pull Request
- Tiene una descripción con `Closes #N`.
- Cambia solo lo que pide el issue.
- Fue revisado por otro integrante.
